# Fresh current-profile native subset (v2)

This is executable acceptance **source**, not permission or native evidence.
No host, credential, grant, trust, ACL, installation, browser or service operation
has been performed by its portable tests. Historical v1 plans still fail before
native work. The independently pinned historical own-restart suite is unchanged.

## Exact supported selection

Use `plan.current.template.json`; its placeholders are deliberately invalid.
The current plan is `tracebolt.windows-linux-native-parity.v2` with exactly:

- `fresh-twenty-one-read-admin-scopes-v1`, unchecked fresh consent v14, receipt12,
  all twenty extension grant digests and their original sender/identity binding;

approval for this harness does not approve native enrollment or collection.
Build all native artifacts from the final committed harness tree, never the base
PR53 commit with a newer source snapshot. The existing full inventory, commit
object, Setup embedded-resource/source-input and Go VCS checks still apply.

## Inputs and approvals needed before any host execution

The two targets, current source/artifact inventory, private network route, private
workspaces, existing trusted TLS/server/issuer material and an authorized custodian
must already exist under separately approved preparation. Use Python 3.12+ x64
with `-I -B`, the source-pinned Go/Node toolchain and lockfile dependencies. There
is no CI native trigger and no permission inferred from plan strings.

The bounded approval must name target IDs and machine hashes; final source
commit/tree and every artifact hash; two exact private TLS origins; custodian and
private paths; start/deadline (at most two hours); and the following operations:

1. Start/stop only the isolated real Linux manager and its sandboxed browser.
   Human performs login, creates the Windows invitation, downloads the public
   bootstrap, approves the public fingerprint and performs two explicit public
   binding transfers. Secrets stay in the supported human/secure handoff.
2. Launch the exact unsigned Windows Setup. Human handles its unsigned-software,
   UAC and any OS security-warning decisions. Human reviews and selects the fresh
   twenty-one scopes, separate automatic-renewal consent, persistent identity and
   limited LocalService installation. Never bypass a security warning, change
   trust/ACL/privileges, or automate hidden invitation entry.
3. Prepare a separately approved task-owned Application event source/resource and
   write exactly one synthetic event. The plan binds source, event ID, text hash
   and message-resource path/hash. The harness never registers a source itself.
4. Explicitly approve one Application history search with the plan's exact UTC
   minute start/end and numeric synthetic event ID, at most 100 returned headers.
   Choose the interval before starting; write the fixture inside it and wait for
   its end before searching. Approve one selected-message request for the exact
   synthetic provider/event/header returned by that search, receipt-linked to its
   original query and fifteen-minute expiry. Human checks the real disclosures

5. Restart only this receipt-owned Tracebolt service once, using the exact current
   artifact; verify its public binding and advancing post-restart inventory.
6. When retention is not needed, remove only the receipt-owned SCM registration
   through the supported `--uninstall --apply` operation. It deliberately retains
   installed files, enrollment/grant receipts and runtime state. This is not full
   data deletion, revocation or target disposal; those need separate approval.
   Never clear Application/System logs or remove third-party resources.

A Windows administrator must deliberately launch the harness elevated, after the
normal human UAC handoff. This is observer/controller access, not a change to the

## Ordered observation

Run only after the approvals above. The existing `run.py --check-plan` is inert.
Native `--execute`, exact target ID, phase and approval reference are required;
CI flags, noninteractive input, stale plans, replayed phases, changed source,
unsafe custody and target mismatch still fail closed.

Start `manager-browser` on Linux. Follow its human login/bootstrap handoff. Run
`setup` on Windows, transfer the tool-generated public endpoint binding unchanged
under private custody, then run `event-fixture`. The browser checks the completed
current receipt/grants, fresh production inventory, original immutable identity
and separately current credential. Provider quality is recorded independently of
protocol success; missing/denied/unsupported/bounded sources never imply coverage.

At the browser's history markers, the human reviews/submits the exact query and
one selected synthetic message. The observer verifies real production response
schemas, consume-once identity, original expiry, receipt, six-field event identity,
message hash and plaintext rendering, then leaves Logs to discard private content.
At its own-restart marker, run `own-restart` and transfer only the resulting public
restart binding. The observer verifies strictly advancing inventory after restart.

Only after the browser and manager have verified cleanup, transfer the exact
sanitized `manager-browser.result.json` unchanged to the Windows private workspace
and independently compare the SHA-256 printed by the Linux coordinator. Supply
that digest as `--browser-report-sha256` only for the current `remove` phase.
`remove` requires that exact transfer-digest/plan/source/artifact-bound
successful result and preceding Windows phase evidence. All output is a finite
sanitized projection with `fullAcceptance: false`; protocol success does not mean
full source availability, retained-history completeness or patch coverage.

## Evidence custody and limits

Keep native inputs, public binding files and sanitized result files private by
default. Do not publish raw inventory, personal labels, event content, credentials,
full native screenshots, browser traces, manager state, private keys or auth files.
The observer keeps private responses in memory and exports finite states/counts
and hashes only. Sharing actual-host evidence with another person/site requires
its own specific data, recipient and purpose approval. Existing invented-data UI
screenshots are not native evidence.

A denied/unavailable/budget-limited provider is a real coverage outcome. It may
coexist with successful enrollment, transport and lifecycle, but cannot establish
usable data for that provider. The single synthetic history case must itself be
observed correctly; unavailable/denied results block that case, not authorize a
broader query or elevated source access. No automatic repair, retry of a consumed
phase, log clearing, manager reset or target substitution is allowed.

## Separate later renewal cutover

A normal leaf lasts up to seven days and enters its renewal window around day five
(with bounded spread). A two-hour fresh session cannot establish native renewal.
The fresh report deliberately says renewal execution was not observed. Injected
renewal integration evidence is separate and cannot fill this native evidence gap.

If later cutover is wanted, separately approve retaining this disposable target,
its original protected manager/endpoint state and issuer custody; do not run the
removal phase. End the initial interactive session cleanly. Record only public
identity anchor, current generation/expiry, exact artifact hashes and prior
sanitized report digest. Plan short, separately authorized linked observation
sessions around the actual due window, retaining the original target and state.
Recheck actual UTC time, live revocation/issuer limits, stable identity/scopes,
current leaf generation and fresh accepted inventory before/after cutover. Link
each session to prior sanitized evidence and exact unchanged artifact inventory.
The fresh-only harness must not be replayed against this used state; later linked
sessions need their own explicitly reviewed observation inputs/procedure.

No fake clock, TTL override, shortened issuer, old evidence relabeling or continuous
multi-day extension of this plan is permitted. Missing the actual observation
window leaves cutover unverified. Retained-host operation, eventual revocation,
receipt-owned removal and target disposal remain separately approved activities.
