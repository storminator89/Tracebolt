# Disposable Mac service installation and removal gate

This is a manual acceptance plan, not evidence that it has run. Execute only on separately approved disposable Apple Silicon and Intel Macs with reviewed source/package artifacts, account/trust/host-service approval, a compatible approved TLS manager, and a deliberate fresh local enrollment. Do not put invitation secrets, private keys, raw telemetry or passwords in logs or test artifacts. No automated test in this repository may apply this gate to an arbitrary host.

1. Record the Mac OS build/architecture, exact source commit, package and binary SHA-256 values and selected UID:GID. Verify package contents and fixed root-owned/no-symlink/ACL-safe installation and source paths. Use the package's explicit create-only preparation stage; record its own receipts. Do not install via a copy of the service CLI in a writable directory.
2. Under the exact dedicated nonroot identity, perform the separately approved fresh TLS `enroll-agent` flow with hidden local invitation entry and independent full public fingerprint/comparison approval. Confirm the activated fixed config, ready marker and original sender state. Do not substitute a basic identity for inventory or reuse an earlier grant. Stop the sender before service preflight.
3. Run the fixed `macos-agent-service --action install` review with exact original profile, UID:GID and selected artifact hashes. Check JSON reports positive local prerequisites, no plist, job or override, no custody, and no mutation. Test foreign plist, registered job, retained disabled/enabled override, altered source/binary, unsafe ACL/path alias, wrong identity, pending enrollment and wrong profile on disposable fixtures; each must block before writes.
4. After explicit host approval, append `--apply` to that same command. Inspect the four durable receipt files, immutable owner and used fence, exact plist bytes, registration path/type/program/arguments and launchctl state. Confirm one service instance, actual nonroot real/effective/saved UID:GID and supplementary groups, and rejection before private reads if launchd starts it under any other identity. Verify the expected lifetime sender lock is owned by the agent while running; registration receipts alone cannot authenticate lock ownership or mutable sender state. A printed registration alone is insufficient.
5. Confirm authenticated fresh real manager observations under the selected Mac profile, with `source=lan` and no synthetic fallback. Check foreground timing, bounded resource behavior and truthful partial/denied sources. Stop the service via separately approved native procedure and verify SIGTERM drain does not reset pending bytes, keys or counters. Test a nonzero exit and observe the actual 30-second throttle/retry semantics; do not describe it as a bounded systemd restart budget.
6. Perform an actual OS reboot. Confirm the same exact launchd job and protected plist are present, the service identity is unchanged, the sender resumes without re-enrollment or sequence reset, and fresh reports continue. Cross-compilation or process restart does not count as this reboot gate.
7. Review `--action uninstall` with the exact original arguments and no `--apply`, then approve and apply exact owned removal. Confirm bootout, the four removal receipts, absent system-domain job and plist, retained used/owner/install receipts, binaries, source archive, account, keys, config, ready marker and sender state. The old identity cannot be freshly installed again by deleting a tombstone.
8. On separate disposable snapshots, interrupt each started phase and inject write/full-flush/close/launchctl errors. Verify no blind retries, foreign deletion, adoption, account/key reset or partial-state cleanup. Preserve the state and report `indeterminate`; manual recovery must be separately designed and approved rather than improvised.

Capture only metadata: command class, exit code, safe JSON status/receipt digests, exact platform, relevant checks and test outcome. Redact any private path if site policy requires it. Never claim Mac release readiness until both architectures pass the approved native gate and package/source hashes match the exact tested bytes.
